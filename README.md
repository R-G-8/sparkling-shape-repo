# numbawatchd

Upload your streaming watch history, rank what you've watched, and get
recommendations from your rankings and your friends'. MGT 656 team project
(team `sparkling-shape`).

## Run locally

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env        # then edit the passwords
set -a; source .env; set +a
python manage.py migrate
python manage.py seed
python manage.py runserver
```

Without `DATABASE_URL`, local development uses SQLite. Staging and production
use Postgres (Neon).

## Tests

```bash
SECRET_KEY=x python manage.py test
```

## Deploy (Render + Neon)

| | Staging | Production |
|---|---|---|
| Render service | `numbawatchd-staging` | `numbawatchd` |
| URL | https://numbawatchd-staging.onrender.com | https://numbawatchd.onrender.com |
| Deploys | every merge to `main` | the `production` branch, moved by **Promote to production** |
| Database | Neon, staging database | Neon, separate production database |

`render.yaml` defines both services. `build.sh` installs, collects static
files, migrates, and seeds on every deploy. Set these in Render for each
service: `DATABASE_URL` (that environment's Neon database),
`GRADER_ADMIN_PASSWORD`, `GRADER_MEMBER_PASSWORD`, and `OPENROUTER_API_KEY`
(the course OpenRouter key, used only on the server).
`SECRET_KEY` is generated by Render. The A/B page lists every member's
nickname by default; `TEAM_MEMBER_NICKNAMES` overrides that list if set.

### Promoting to production

1. Merge to `main`; staging deploys and CI runs.
2. Check the change on staging.
3. In GitHub, open **Actions → Promote to production → Run workflow**. It
   fast-forwards the `production` branch to `main` (or the commit you give it),
   but only if CI passed for that commit. Render then deploys production.

To roll back, revert the change on `main` and promote again; the workflow never
rewrites `production`.

### Setting up production (once)

1. **Neon:** create a separate production database (a new Neon project such as
   `numbawatchd-production`) and copy its connection string.
2. **GitHub:** run **Promote to production** once; that creates the
   `production` branch.
3. **Render:** if staging was created from this Blueprint, sync the Blueprint
   and Render offers to create `numbawatchd`. Otherwise create a Web Service by
   hand: this repo, branch `production`, name `numbawatchd`, build
   `./build.sh`, start `gunicorn config.wsgi --bind 0.0.0.0:$PORT --log-file -`,
   health check `/healthz`, and environment variables `PYTHON_VERSION=3.13.3`,
   `SECRET_KEY` (generate), `DATABASE_URL` (production Neon),
   `GRADER_ADMIN_PASSWORD`, `GRADER_MEMBER_PASSWORD`, `OPENROUTER_API_KEY`.
4. Open `/healthz`, `/login`, and `/e1531ff` on the production URL.
